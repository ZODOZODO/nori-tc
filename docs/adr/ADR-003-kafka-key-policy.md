# ADR-003: Kafka 메시지 Key 규칙 고정

## 상태
승인됨 (2026-02-19)

## 배경
- 파티션 순차성은 같은 key를 공유하는 메시지 집합 단위로만 보장됩니다.
- 도메인별 순차성 기준이 명확하지 않으면 재처리 시 순서 역전, 중복 커밋, 재시도 불일치 문제가 발생합니다.

## 결정
- `tc.mes.events`, `tc.mes.commands`의 key는 `correlationId`를 사용합니다.
- 그 외 토픽(`tc.eqp.events`, `tc.eqp.commands`, `tc.ui.events`, `tc.ui.commands`)의 key는 `eqpid`를 사용합니다.

## 세부 규칙
1. key는 공백/빈 문자열을 허용하지 않습니다.
2. MES 토픽에서 `correlationId`가 없으면 메시지는 유효성 실패로 처리합니다.
3. 비-MES 토픽에서 `eqpid`가 없으면 메시지는 유효성 실패로 처리합니다.
4. key 생성 로직은 모듈별 중복 구현 대신 공통 리졸버를 사용합니다.

## 결과
- 토픽별 순차성 단위가 고정되어 커밋/재시도 정책과 일관되게 동작합니다.
- 애플리케이션별 임의 key 규칙을 제거하여 운영 중 추적 가능성을 높입니다.
