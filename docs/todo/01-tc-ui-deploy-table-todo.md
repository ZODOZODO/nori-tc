# TODO: tc_ui_deploy / tc_ui_deploy_scenario 테이블 추가

## 1. 개요

배포(Deploy) 기능을 지원하기 위한 두 개의 신규 테이블을 추가한다.
배포 시나리오 마스터(`tc_ui_deploy_scenario`)와 실제 배포 실행 이력(`tc_ui_deploy`)으로 구성되며,
하나의 배포는 하나의 배포 시나리오를 가진다.

---

## 2. 테이블 관계

```text
tc_ui_deploy_scenario (1) ──────> (N) tc_ui_deploy
  deploy_scenario_key                  deploy_scenario_key (FK)
```

- `tc_ui_deploy_scenario` : 배포 시나리오 마스터 테이블
- `tc_ui_deploy` : 배포 실행 이력 테이블 (시나리오 1건에 배포 N건)

---

## 3. 테이블 명세

### 3-1. `tc_ui_deploy_scenario` - 배포 시나리오 마스터

| 컬럼명               | 타입           | 제약                        | 설명                    |
|---------------------|---------------|-----------------------------|-------------------------|
| deploy_scenario_key | BIGINT        | PK, IDENTITY                | 배포 시나리오 PK         |
| deploy_scenario     | VARCHAR(64)   | NOT NULL, UNIQUE            | 배포 시나리오 식별 코드  |
| scenario_name       | VARCHAR(128)  | NOT NULL                    | 배포 시나리오 표시 이름  |
| description         | VARCHAR(2000) | NULL                        | 설명                    |
| created_at          | TIMESTAMPTZ(3)| NOT NULL, DEFAULT NOW()     | 생성 일시               |
| updated_at          | TIMESTAMPTZ(3)| NOT NULL, DEFAULT NOW()     | 수정 일시               |
| created_by          | VARCHAR(50)   | NOT NULL, DEFAULT 'SYSTEM'  | 생성자                  |
| updated_by          | VARCHAR(50)   | NOT NULL, DEFAULT 'SYSTEM'  | 수정자                  |

- PK: `pk_tc_ui_deploy_scenario` → `deploy_scenario_key`
- Unique: `uk_tc_ui_deploy_scenario_deploy_scenario` → `deploy_scenario`
- Index: `deploy_scenario`

---

### 3-2. `tc_ui_deploy` - 배포 실행 이력

| 컬럼명               | 타입           | 제약                        | 설명                                                  |
|---------------------|---------------|-----------------------------|-------------------------------------------------------|
| process_id          | VARCHAR(23)   | PK                          | 배포 프로세스 ID (형식: `yyyyMMddHHmmss_랜덤8자리`)    |
| deploy_scenario_key | BIGINT        | NOT NULL, FK                | 배포 시나리오 FK (`tc_ui_deploy_scenario`)            |
| description         | VARCHAR(2000) | NULL                        | 배포 설명                                             |
| status              | VARCHAR(16)   | NOT NULL                    | 배포 상태 (예: PENDING, RUNNING, SUCCESS, FAILED)     |
| created_at          | TIMESTAMPTZ(3)| NOT NULL, DEFAULT NOW()     | 생성 일시                                             |
| updated_at          | TIMESTAMPTZ(3)| NOT NULL, DEFAULT NOW()     | 수정 일시                                             |
| created_by          | VARCHAR(50)   | NOT NULL, DEFAULT 'SYSTEM'  | 생성자                                                |
| updated_by          | VARCHAR(50)   | NOT NULL, DEFAULT 'SYSTEM'  | 수정자                                                |

- PK: `pk_tc_ui_deploy` → `process_id`
- FK: `fk_tc_ui_deploy_deploy_scenario_key__tc_ui_deploy_scenario`
  - `deploy_scenario_key` → `tc_ui_deploy_scenario.deploy_scenario_key` `ON DELETE RESTRICT`
- Index: `deploy_scenario_key`, `status`

> **process_id 생성 규칙**
> - 형식: `yyyyMMddHHmmss` + `_` + 8자리 랜덤 숫자
> - 예: `20240311143022_12345678`
> - 애플리케이션 레이어에서 생성하며, DB 자동 생성(IDENTITY)을 사용하지 않는다.

## 5. DDL 예시 (PostgreSQL)

```sql
-- 배포 시나리오 마스터
CREATE TABLE public.tc_ui_deploy_scenario (
    deploy_scenario_key BIGINT GENERATED BY DEFAULT AS IDENTITY,
    deploy_scenario     VARCHAR(64)    NOT NULL,
    scenario_name       VARCHAR(128)   NOT NULL,
    description         VARCHAR(2000)  NULL,
    created_at          TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by          VARCHAR(50)    NOT NULL DEFAULT 'SYSTEM',
    updated_by          VARCHAR(50)    NOT NULL DEFAULT 'SYSTEM',

    CONSTRAINT pk_tc_ui_deploy_scenario PRIMARY KEY (deploy_scenario_key),
    CONSTRAINT uk_tc_ui_deploy_scenario_deploy_scenario UNIQUE (deploy_scenario)
);

CREATE INDEX ix_tc_ui_deploy_scenario_deploy_scenario ON public.tc_ui_deploy_scenario (deploy_scenario);

-- 배포 실행 이력
CREATE TABLE public.tc_ui_deploy (
    process_id          VARCHAR(23)    NOT NULL,
    deploy_scenario_key BIGINT         NOT NULL,
    description         VARCHAR(2000)  NULL,
    status              VARCHAR(16)    NOT NULL,
    created_at          TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by          VARCHAR(50)    NOT NULL DEFAULT 'SYSTEM',
    updated_by          VARCHAR(50)    NOT NULL DEFAULT 'SYSTEM',

    CONSTRAINT pk_tc_ui_deploy PRIMARY KEY (process_id),
    CONSTRAINT fk_tc_ui_deploy_deploy_scenario_key__tc_ui_deploy_scenario
        FOREIGN KEY (deploy_scenario_key) REFERENCES public.tc_ui_deploy_scenario(deploy_scenario_key) ON DELETE RESTRICT,
    CONSTRAINT ck_tc_ui_deploy_status CHECK (status IN ('PENDING', 'RUNNING', 'SUCCESS', 'FAILED'))
);

CREATE INDEX ix_tc_ui_deploy_deploy_scenario_key ON public.tc_ui_deploy (deploy_scenario_key);
CREATE INDEX ix_tc_ui_deploy_status              ON public.tc_ui_deploy (status);
CREATE INDEX ix_tc_ui_deploy_created_at          ON public.tc_ui_deploy (created_at);
```
