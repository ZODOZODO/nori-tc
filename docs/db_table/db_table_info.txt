[nori-tc DB 구조 요약]

1) 모델/버전 분리
- tc_model: 모델 원장(모델명, maker, comm_interface)
- tc_model_version: 모델 버전 원장(model_version, status)
- 관계: tc_model(1) : tc_model_version(n)

2) 버전 기준 참조(핵심)
- tc_eqp.model_version_key -> tc_model_version.model_version_key
- 모든 tc_model_* 하위 테이블도 model_version_key FK 사용

3) 카디널리티
- tc_model_version(1):tc_eqp(n)
- tc_model_version(1):tc_model_param(n)
- tc_model_version(1):tc_model_secs_message(n) — UNIQUE(model_version_key, secs_msg_name)
- tc_model_version(1):tc_model_socket_message(n) — UNIQUE(model_version_key, socket_msg_name)
- tc_model_version(1):tc_model_mes_message(n) — UNIQUE(model_version_key, mes_msg_name)
- tc_model_version(1):tc_model_variableid(n)
- tc_model_version(1):tc_model_reportid(n)
- tc_model_version(1):tc_model_eventid(n)
- tc_model_version(1):tc_model_workflow(n)
- tc_model_version(1):tc_model_mdf(1)
- tc_model_version(1):tc_model_dcop_item(n)

4) 1:1 강제 테이블(UNIQUE model_version_key)
- tc_model_mdf

5) 소유권 원칙
- maker, comm_interface는 tc_model 소유
- model_version, status는 tc_model_version 소유
